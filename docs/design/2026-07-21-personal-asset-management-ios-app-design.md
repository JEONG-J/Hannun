# 개인 자산관리 iOS 앱 — 설계 문서

- 작성일: 2026-07-21
- 상태: 승인됨 (구현 계획 수립 대기)

## 1. 개요

개인용 자산관리 iOS 앱. 현금, 국내/해외 주식·ETF, 코인(업비트 상장 기준)을 한 곳에서 추적하고,
순자산 현황 / 포트폴리오 상세 / 기간별 투자 성과 / 매매일지를 하나의 앱에서 관리한다.

### 범위 (Scope)
- 포함: 순자산 추적, 포트폴리오 관리, 투자 성과(수익률) 추적 및 벤치마크 비교, 매매일지
- 제외: 가계부(수입/지출) 기능, 은행/증권사 자동 연동(오픈뱅킹 등), 앱 자체 잠금(생체인증)

### 타겟
- iOS 26.0 이상, 개인(1인) 사용, 여러 기기(아이폰/아이패드) 간 데이터 동기화 필요
- 배포 타깃을 iOS 26.0으로 확정한 이유: UI 스펙이 Liquid Glass·`tabViewBottomAccessory`·
  `ConcentricRectangle` 같은 iOS 26 전용 API를 전제로 작성됐다. 하위 버전은 지원하지 않는다
  (`docs/design/2026-07-30-tuist-module-target-spec.md` §1·§11-①)

## 2. MVP 범위

4개 탭(순자산/포트폴리오/성과/매매일지) 전부를 MVP에 포함한다. 별도 기능 단계(2차 출시 등)로 미루는
탭은 없으며, "MVP"는 각 기능을 아래 [기능 명세서](#6-기능-명세서)에 정의된 최소 구현 수준으로
한정한다는 의미로 사용한다. 즉 명세서에 없는 부가 기능(알림, 위젯, 앱 잠금, 가계부, 자동 연동 등)은
1차 출시 범위에서 제외한다.

## 3. 아키텍처

- **SwiftUI** 기반 앱
- **SwiftData**로 로컬 영속성 처리, CloudKit 연동을 통해 기기 간 자동 동기화 (별도 백엔드 서버 없음)
- 계층 구조: `View(SwiftUI)` → `ViewModel(Observable)` → `Service` → `SwiftData 모델`
- 시세/환율/벤치마크 데이터는 `MarketDataService` 프로토콜로 추상화하여 구현체 교체가 용이하도록 함
  - **코인 (보유 + 비트코인 벤치마크)**: 업비트 공개 API
  - **국내/해외 주식·ETF, 환율, 벤치마크 지수(코스피/S&P500/나스닥)**: 한국투자증권(KIS) Open API로 통합
  - 외부 API는 총 2개(KIS, 업비트)만 사용하여 인증 방식·레이트리밋 관리 부담을 최소화 (상세는 [11. 외부 API 명세서](#11-외부-api-명세서) 참고)

### 데이터 흐름
1. 사용자가 보유 종목(수량, 평단가)을 수동으로 입력
2. `MarketDataService`가 현재가/환율을 주기적으로(또는 수동 새로고침 시) 조회하여 로컬에 캐싱
3. 평가금액·수익금·수익률은 저장하지 않고 `수량 × 현재가`와 `수량 × 평단가`로 그때그때 계산
4. 매월초(및 일별)에 `NetWorthSnapshot`을 자동 생성하여 성과 탭의 추이 그래프에 사용

## 4. 데이터 모델 (SwiftData 엔티티)

엔티티 5종은 CloudKit 동기화를 켠 하나의 `ModelContainer` 에 등록된다. 이때
**모든 저장 프로퍼티는 optional 이거나 기본값을 가져야 하고, `@Attribute(.unique)` 는 쓸 수 없다.**
따라서 아래 표는 "필수/null" 이 아니라 **모델이 들고 태어나는 기본값**을 적고, 사용자 입력이 반드시
있어야 하는 값은 모델 제약이 아니라 **상위 계층의 검증 규칙**으로 다룬다.
제약의 원문은 `docs/design/2026-07-30-tuist-module-target-spec.md` §9.2 다.

| 엔티티 | 주요 필드 (모델 기본값) | 설명 |
|---|---|---|
| **Holding** | 자산유형(현금/국내주식/해외주식/ETF/코인, 기본 현금), 종목명·티커(기본 빈 문자열), 통화(기본 KRW), 수량(기본 0), 평단가(optional — 현금은 nil) | 보유 자산 1건 |
| **CashFlowEvent** | 날짜(기본 현재), 금액(기본 0), 통화(기본 KRW), 유형(입금/출금, 기본 입금), 메모(기본 빈 문자열) | 성과(수익률) 계산 시 제외할 입출금 기록 |
| **NetWorthSnapshot** | 날짜(기본 현재), 총자산 KRW·USD(기본 0), 카테고리별 소계(기본 빈 목록) | 매월초 기준 자동 기록되는 자산 스냅샷 (일별 스냅샷도 병행) |
| **BenchmarkSnapshot** | 날짜(기본 현재), 지수명(코스피/S&P500/나스닥/BTC, 기본 빈 문자열), 값(기본 0) | 벤치마크 비교 차트용 캐시 데이터 |
| **JournalEntry** | 날짜(기본 현재), 제목·본문(기본 빈 문자열), 연결된 Holding(기본 빈 목록 — 양방향 optional 관계) | 매매일지 1건 |

### 필수값·중복 방지는 모델 밖에서 지킨다

기본값을 가진 모델은 "빈 제목", "수량 0" 같은 값도 그대로 저장할 수 있다. 그래서 명세가 요구하는
필수 입력과 중복 방지는 저장 **전에** 상위 계층이 판정한다. 검증을 두 곳에 두는 이유는 역할이
다르기 때문이다 — ViewModel 은 저장 버튼을 막고 사유를 화면에 보여주며(입력 폼 인라인 에러),
UseCase 는 어느 화면에서 호출되든 잘못된 값이 저장소에 닿지 않게 하는 최종 관문이다.

| 규칙 | 관련 기능 | 검증 계층 |
|---|---|---|
| 종목명이 비어 있으면 저장 불가, 수량은 0보다 커야 함 | PF-2, PF-3 | 종목 편집 ViewModel(인라인) + 종목 저장 UseCase |
| 현금이 아닌 자산은 평단가가 있어야 함 | PF-2 | 종목 저장 UseCase |
| 같은 자산유형·티커의 Holding 중복 등록 방지 | PF-2 | 종목 저장 UseCase — 저장 전 조회 후 판정 |
| 금액이 0보다 커야 함 | PF-5, PF-6 | 입출금 ViewModel(인라인) + 입출금 UseCase |
| 같은 날짜의 NetWorthSnapshot 중복 기록 방지 | PM-1 | 스냅샷 기록 UseCase — 소급 계산 시 기존 날짜 조회 후 판정 |
| 같은 (지수명, 날짜)의 BenchmarkSnapshot 중복 캐싱 방지 | PM-4 | 벤치마크 캐시 저장 지점 — 조회 후 갱신/삽입 결정 |
| 제목이 비어 있으면 저장 불가 | JR-2 | 일지 작성 ViewModel(인라인) + 일지 저장 UseCase |

- **유니크 제약(`@Attribute(.unique)`)은 어떤 엔티티에도 쓰지 않는다.** 위 표의 "중복 방지" 세 줄이
  그 대안이다 — 저장 직전에 같은 키의 레코드를 조회해 있으면 갱신, 없으면 삽입한다.
  개인용 1인 앱이라 동시 쓰기 경합이 사실상 없어 이 방식으로 충분하다.
- **관계는 양방향·optional 로 선언한다.** `JournalEntry` ↔ `Holding` 연결(0개 이상)은 양쪽에
  inverse 관계를 두어야 CloudKit 스키마 검증을 통과한다.

## 5. 화면 구성

### 5.1 순자산 탭
- 상단에 총자산을 큰 숫자로 표시, KRW/USD 토글 스위치로 기준 통화 전환
- 자산군별(현금/국내주식/해외주식/ETF/코인) 비중 파이차트
- 하단에 카테고리별 소계 리스트 — 탭 시 포트폴리오 탭의 해당 필터로 이동

### 5.2 포트폴리오 탭
- 보유 종목 리스트 (카테고리별 그룹핑), 각 항목에 수량·평단가·현재가·평가금액·수익금·수익률 표시
- 종목 추가/수정/삭제 (수량, 평단가 입력)
- 입출금 기록 관리 서브 화면 (입금/출금 내역 추가·조회·삭제)

### 5.3 성과 탭
- 총자산 추이 라인 차트, 일별/월별 토글 가능 (기준은 매월초 스냅샷)
- 연초(1/1) 대비 YTD 수익률을 큰 숫자로 표시 — **입출금(CashFlowEvent)은 제외한 순수 투자 성과**만 반영
- 코스피/S&P500/나스닥/비트코인과의 수익률 비교 라인 차트 (동일 기간, 동일 %기준으로 오버레이)

### 5.4 매매일지 탭
- 일지 리스트: 날짜 자동 표시 + 제목, 최신순 정렬
- 작성 화면: 제목, 본문(자유 서술형), 연결 종목 태그(0개 이상 다중 선택 — 자유 작성도 가능, 종목 연결은 선택 사항)
- 특정 종목으로 필터링하여 해당 종목 관련 일지만 모아보기

각 기능은 MVP(1차 출시) 범위에 포함되는 최소 구현 단위를 기준으로 기술한다.

|---|---|---|---|---|---|

| JR-4 | 종목별 필터링 | 특정 종목에 연결된 일지만 모아보기 | 종목 선택 | 해당 종목 태그가 달린 JournalEntry만 표시 | - |

## 7. 외부 연동 (시세/환율/벤치마크)

- `MarketDataService` 프로토콜로 추상화, 외부 API는 KIS(한국투자증권)와 업비트 2개만 사용
- 마지막 조회 결과를 로컬에 캐싱, 일정 시간(예: 15분) 이내 재조회 시 캐시 사용 (API 호출 절약 + 오프라인 대응)
- 앱 포그라운드 진입 시 또는 pull-to-refresh로 갱신
- 상세 엔드포인트/인증 방식은 [11. 외부 API 명세서](#11-외부-api-명세서) 참고

## 8. 에러 처리 / 엣지 케이스

- **네트워크 없음 / API 실패**: 마지막으로 성공한 가격을 그대로 표시하고, "갱신 실패 · n분 전 기준" 배지로 사용자에게 알림 (빈 화면이나 크래시 없이 degrade)
- **시세 데이터가 없는 신규/미지원 종목**: 수동으로 현재가를 임시 입력할 수 있는 폴백 제공
- **입출금 기록 수정/삭제 시**: 관련된 성과 계산(YTD 수익률, 추이 그래프)을 자동 재계산
- **월초 스냅샷 시점에 앱을 실행하지 않은 경우**: 다음 실행 시 놓친 기간을 소급 계산하여 채워 넣음 (해당 기간 보유 내역 기준)

## 9. 테스트 전략

- 핵심 계산 로직(수익률, 원화/달러 환산, YTD 계산, 입출금 제외 로직)은 ViewModel/계산 서비스 단위 테스트로 검증
- `MarketDataService`는 프로토콜로 추상화되어 있어 테스트에서 mock 데이터로 대체 가능 (실제 API 호출 없이 계산 로직 검증)
- UI는 개인용 앱 특성상 자동화된 E2E보다 실기기 수동 확인 위주

## 11. 외부 API 명세서

외부 API는 **한국투자증권(KIS) Open API**와 **업비트 공개 API** 2개만 사용한다. 각 앱 내부 기능은
`MarketDataService` 프로토콜 뒤에 숨겨지므로, 아래 두 API 중 하나가 바뀌어도 나머지 코드에는 영향이 없다.

### 11.0 외부에서 가져와야 하는 데이터 (요약)

앱이 직접 계산/생성하지 않고 **외부 API로 가져와야만 하는 데이터**는 아래 5가지다. 이 외의 데이터
(보유 수량, 평단가, 입출금 기록, 매매일지, 수익률 계산 결과 등)는 전부 사용자가 입력하거나 앱이
직접 계산한다.

| 외부에서 가져오는 데이터 | 출처 | 사용처 |
|---|---|---|
| 국내 주식/ETF 현재가 | KIS | 포트폴리오 평가금액, 순자산 |
| 해외(미국) 주식/ETF 현재가 | KIS | 포트폴리오 평가금액, 순자산 |
| 코인 현재가 | 업비트 | 포트폴리오 평가금액, 순자산 |
| USD/KRW 환율 | KIS | KRW/USD 통화 환산 |
| 벤치마크 지수(코스피/S&P500/나스닥/비트코인) 시세 | KIS(지수), 업비트(BTC) | 성과 탭 벤치마크 비교 차트 |

### 11.1 업비트 (코인 시세)

| 항목 | 내용 |
|---|---|
| 용도 | 보유 코인 현재가, 비트코인 벤치마크 시세 |
| Base URL | `https://api.upbit.com` |
| 인증 | 불필요 (Quotation API는 공개, API 키 없이 호출 가능) |
| 주요 엔드포인트 | `GET /v1/ticker?markets=KRW-BTC,KRW-ETH,...` |
| 요청 파라미터 | `markets`: 콤마로 구분한 마켓 코드 (예: `KRW-BTC`) |
| 응답 주요 필드 | `market`(마켓코드), `trade_price`(현재가, KRW), `signed_change_rate`(전일대비 등락률), `trade_timestamp` |
| Rate limit | 공개 시세 API는 초당 요청 수 제한 있음(수 회/초 수준) — 앱 내 캐싱(15분 주기)으로 여유있게 대응 |
| 비고 | 업비트에 상장되지 않은 코인은 조회 불가 → PF-2(종목 추가) 시 미지원 코인은 현재가 수동 입력 폴백 사용 |

### 11.2 한국투자증권(KIS) Open API (국내/해외 주식·ETF, 지수, 환율)

| 항목 | 내용 |
|---|---|
| 용도 | 국내·해외 주식/ETF 시세, 코스피/S&P500/나스닥 지수 시세, USD/KRW 환율 |
| Base URL | 실전투자 `https://openapi.koreainvestment.com:9443` (모의투자 도메인도 별도 존재) |
| 인증 | OAuth2 client-credentials 방식. 앱키(appkey)·앱시크릿(appsecret)을 증권 계좌로 발급받아 앱에 안전하게 보관 → `POST /oauth2/tokenP` 호출로 접근토큰(access_token) 발급 → 토큰 만료 전 자동 갱신 |
| 국내주식/ETF 시세 | 국내주식 현재가 시세 조회 API (헤더의 `tr_id`로 거래 종류 구분) |
| 해외주식/ETF 시세 | 해외주식 현재가 시세 조회 API |
| 국내지수(코스피) | 국내 지수 시세 조회 API |
| 해외지수(S&P500/나스닥) | 해외 지수 시세 조회 API |
| 환율(USD/KRW) | 해외주식 관련 환율 조회 API (원화 환산 시 사용) |
| Rate limit | 계정당 초당 호출 건수 제한 있음 — 앱 내 캐싱(15분 주기)으로 대응 |
| 비고 | 정확한 엔드포인트 경로·요청 헤더(`tr_id` 값 등)·응답 스키마는 KIS 공식 개발자 문서가 수시로 갱신되므로, **구현 착수 시점에 최신 문서 기준으로 재확인 필요**. 접근토큰 발급/갱신 로직은 앱 내 별도 인증 모듈로 분리 |

### 11.3 공통 사항

- 두 API 모두 실패 시 [8. 에러 처리](#8-에러-처리--엣지-케이스)의 "마지막 캐시값 사용 + 갱신 실패 배지" 정책을 따른다
- API 키(KIS appkey/appsecret)는 클라이언트 앱 내 안전한 저장소(Keychain)에 보관하고, 소스 코드나 저장소에 커밋하지 않는다
